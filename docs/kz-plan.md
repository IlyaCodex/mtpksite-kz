## Как устроены языки

Содержимое одно — русское, в базе. Переводы — словарём «русская строка → перевод», таблица `content.translations`
(`kz`, `en`). Страница собирается на русском, затем готовый HTML один раз проходит `content-kit/i18n.ts`
(`_document.tsx`): текст и подписи заменяются по словарю, адреса получают приставку языка. Строка без перевода
остаётся русской. Компонентам о языке знать не нужно; фото, характеристики и ссылки на всех языках одни.

Так был устроен и живой .kz: каждой русской строке там соответствует ровно один перевод.

- Адрес и язык: `src/proxy.ts`, `pages/[[...slug]].tsx`; canonical и hreflang: `components/SiteHead.tsx`;
  карта сайта: `lib/sitemap.ts`; перегенерация страниц на всех языках: `pages/api/revalidate.ts`.
- Режим `next dev` для проверки языков не годится: React в браузере заменяет перевод русским. Проверять на сборке
  (`npm run build:web`, затем `next start --port 3400` в `apps/web`).

Что вставляют скрипты браузера (таблица сравнения, окно поиска, подсказки форм), приводит к языку `apps/web/src/client/i18n.ts`:
адреса — всегда, текст — по словарю `/data/ui-strings.json`; строки для него перечислены в `content-kit/ui-strings.ts`
(создаёт `scripts/kz/ui-strings.ts`, запускать после правки текстов в скриптах). Страница 404 одна, русская: на /kz/ и /en/ её
переводит этот же модуль. Поиск: в индексе у страницы по документу на язык, адрес с приставкой. Правка словаря — админка, «Переводы».

Хранилище S3 общее с основным сайтом: новые файлы этого сайта — только в `img/kz/…`, `files/kz/…`, вложения заявок — в `leads/kz/…`;
файлы основного сайта отсюда не удаляются (`services/media/src/index.ts`).

## Скрипты (`platform/scripts/kz/`)

Содержимое собирается так (всё можно запускать повторно, база — локальная копия):

1. `crawl-live.ts`, `crawl-extra.ts` — копия живого сайта в `exports/kz-live/` (исходник переводов и своих страниц, в git не попадает).
2. `import-translations.ts` — словарь из этой копии: страницы трёх языков сопоставляются строка за строкой.
3. `regional-pairs.ts` → `regionalize.ts` (правила — `regional-rules.ts`) — тексты основного сайта в базе приводятся к Казахстану:
   готовые пары с живых страниц, затем правила. После новой копии товаров с основного сайта запускается снова.
4. `build-content.ts` — главная, настройки, свои страницы с живого сайта (контакты, о компании, политика, согласие, реестр проектов
   и кейсы), данные карты и кейсов (`apps/web/src/legacy/{projects,cases}-data*.ts`), перенаправления, заголовки страниц с живого сайта.
5. `missing-translations.ts` → `translate-batches.ts` → перевод пачек → `import-machine.ts` — недостающие строки (origin=machine).

## Локальный запуск

Настройки — свой `platform/.env`; порты свои, можно работать рядом с основным сайтом: Postgres 5443, Redis 6393,
сайт 3400, админка 3500, сервисы 4201–4205. В базе — копия содержимого основного сайта на 02.11.2026 (страницы и каталог,
без заявок и пользователей) и словарь.
